## base

SHA-256 is a cryptographic hash function that takes any input and produces a fixed 256-bit (32-byte) output, called a digest or hash. The same input always produces the same output, but even a tiny change in the input produces a completely different hash. You cannot reverse a hash to recover the original input.

Bitcoin uses SHA-256 everywhere. Mining, transaction identifiers, and address derivation all depend on it. In most cases Bitcoin applies SHA-256 twice in a row, a pattern called double-SHA-256 or SHA-256d.

![SHA-256 Compression Round](media/wiki/sha-256/sha256-round.svg "A single round of the SHA-256 compression function: the message schedule feeds into the round function with 8 working variables, and the state update propagates to the next round.")

Miners hash the block header with double-SHA-256. The first hash produces an intermediate 256-bit result, and the second hash produces the final output. If that output is below the network target, the block is valid. This is the core of Bitcoin's proof of work.

Each transaction gets its own identifier, the txid, which is the double-SHA-256 of the serialized transaction data. Every Bitcoin address is derived by hashing a public key first with SHA-256 and then with RIPEMD-160. In all these uses, SHA-256 plays the role of a reliable fingerprint machine: it turns data into a compact, unforgeable identifier.

## medium

SHA-256 belongs to the SHA-2 family designed by NIST. It uses a Merkle-Damgård construction, which means it processes data in fixed-size blocks of 512 bits (64 bytes). If the input is shorter than a full block, padding is added. If it is longer, the input is split into multiple blocks and each block is processed sequentially, with the output of one block feeding into the next.

The internal state consists of eight 32-bit working variables labeled A through H. Each block goes through 64 rounds of a compression function. In every round, the algorithm computes two temporary values:

- T1 = H + Σ1(E) + Ch(E, F, G) + Kt + Wt
- T2 = Σ0(A) + Maj(A, B, C)

These values update A and E, and then all eight registers shift: the old A becomes B, old B becomes C, old C becomes D, old D becomes E after the update, and so on. After 64 rounds, the working variables are added to the previous hash state to produce the output for that block.

Bitcoin uses double-SHA-256 for proof of work because a single SHA-256 is vulnerable to a length-extension attack: given H(M), an attacker can compute H(M || padding || extension) without knowing M. Double-hashing removes this property. For mining, the first hash processes the 80-byte block header padded to two 64-byte blocks, and the second hash processes the 32-byte result padded to one block.

The 256-bit output provides 128 bits of security against collision attacks and 256 bits against preimage attacks. No practical collision has been found, and the best known attacks are still theoretical and far from threatening Bitcoin's use.

## advanced

The SHA-256 algorithm initialises eight 32-bit constants H0 through H7, derived from the fractional parts of the square roots of the first eight primes. These become the initial values for A through H before the first block is processed. Sixty-four round constants Kt are derived from the fractional parts of the cube roots of the first sixty-four primes.

The message schedule Wt is an array of sixty-four 32-bit words. The first sixteen words come directly from the 512-bit input block. The remaining forty-eight are computed recursively:

- Wt = σ1(Wt-2) + Wt-7 + σ0(Wt-15) + Wt-16

The σ0 and σ1 functions perform bitwise rotations and shifts. The compression function uses two more bitwise functions:

- Σ0(A) = ROTR-2(A) ⊕ ROTR-13(A) ⊕ ROTR-22(A)
- Σ1(E) = ROTR-6(E) ⊕ ROTR-11(E) ⊕ ROTR-25(E)
- Ch(E, F, G) = (E ∧ F) ⊕ (¬E ∧ G)
- Maj(A, B, C) = (A ∧ B) ⊕ (A ∧ C) ⊕ (B ∧ C)

The padding scheme appends a 1 bit, then enough zero bits to reach 448 bits modulo 512, and finally a 64-bit big-endian representation of the original message length. This ensures that even an empty message produces a full block.

Endianness is a subtle but critical detail in Bitcoin. SHA-256 itself works in big-endian: bytes are consumed from most significant to least significant. Bitcoin's proof of work treats the block header hash as a big-endian 256-bit integer when comparing it to the target. However, when Bitcoin uses SHA-256 as an intermediate step for address generation (SHA-256 followed by RIPEMD-160), the internal endianness conventions of RIPE-MD 160 effectively invert the byte order from the SHA-256 output. Developers working on address generation must pay careful attention to byte ordering or they will derive the wrong address.

Security considerations: SHA-256 provides 256-bit preimage resistance, which is sufficient against classical computers. Grover's algorithm on a sufficiently large quantum computer would reduce the brute-force search to 128 bits. While this is a long-term concern, the more immediate quantum threat is to ECDSA, not to hash functions. The SHA-256 algorithm itself is still considered secure for all Bitcoin use cases as of 2026.
